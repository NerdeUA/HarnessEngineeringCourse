## Корпус і методика

Корпус містить вісім описів, побудованих за оголошеними об’єктами живого кластера: Service і StatefulSet Qdrant, `default-model-config`, `k8s-agent`, обидва retrieval-агенти та обидва MCPServer. У двох колекціях текст і поля `source`, `kind`, `namespace`, `name` однакові. Записи додано storage-інструментом кожного MCP. Згенеровані Pods, Secrets і об’єкти контролерів не індексувалися.

До retrieval tool кожного MCP надіслано чотири фіксовані запити. Ранг — позиція очікуваного об’єкта у відповіді MCP; для останнього запиту, де релевантні обидва агентські записи, враховано перший релевантний ранг. Метрики — Hit@k і середній reciprocal rank (MRR), а не якість LLM-відповідей.

| Запит | Очікуваний запис(и) | Ранг MiniLM | Ранг baseline |
|---|---|---:|---:|
| Який Kubernetes Service відкриває HTTP REST API Qdrant і на якому порту? | `Service/qdrant` | 2 | 1 |
| Яка embedding-модель і колекція налаштовані для офіційного Qdrant MCP? | `MCPServer/qdrant-minilm` | 2 | 1 |
| Який Kubernetes-агент має інструменти для читання логів Pod та перевірки зв’язності сервісів? | `Agent/k8s-agent` | 1 | 1 |
| Чим відрізняються baseline та official retrieval-агенти за MCP-інструментами й колекціями? | `Agent/retrieval-agent`, `Agent/retrieval-agent-official` | 1, 2 | 1, 2 |

| Метрика | Офіційний MiniLM | Baseline ABox |
|---|---:|---:|
| Hit@1 (перший релевантний запис у запиті) | 2/4 | 4/4 |
| Hit@3 | 4/4 | 4/4 |
| MRR | 0,75 | 1,00 |

У кожній колекції Qdrant міститься по вісім точок. `indexed_vectors_count` дорівнює нулю, оскільки малий корпус нижче стандартного порога побудови HNSW; перевірені запити Qdrant обслуговує повним скануванням. Жива конфігурація показує окремий 384-вимірний вектор MiniLM і 768-вимірний базовий вектор.

## Оцінювання агентів

Після виправлення спільного OpenAI credential A2A endpoint успішно завершив усі вісім задач retrieval-агентів (HTTP 200, стан `completed`); вміст Secret не читався. До кожного агента надіслано однакові чотири запитання. Для кожного запитання відома цільова інформація в індексованому корпусі. Відповідь зараховано як правильну, якщо вона містить цільовий факт і посилається на відповідний запис/джерело.

| Запит | Відповідь baseline | Інструмент baseline | Відповідь official | Інструмент official |
|---|---|---|---|---|
| Q1: REST Service Qdrant і порт | Правильно: `Service/qdrant`, порт `6333` | `vector_find` | Правильно: `Service/qdrant`, порт `6333` | `qdrant-find` |
| Q2: embedding-модель і колекція офіційного MCP | Неправильна відмова: запитано порожній граф, запис MCPServer не знайдено | `get-schema` | Правильно: `sentence-transformers/all-MiniLM-L6-v2`, `abox-minilm` | `qdrant-find` |
| Q3: агент з інструментами читання логів Pod і перевірки зв’язності | Неправильна відмова: запитано порожній граф, запис Agent не знайдено | `get-schema` | Правильно: `k8s-agent`, названо обидва інструменти | `qdrant-find` |
| Q4: порівняння інструментів і колекцій агентів | Правильно: baseline `vector_store`/`vector_find`, `abox-nomic`; official `qdrant-store`/`qdrant-find`, `abox-minilm` | `vector_find` | Правильно, з посиланнями на обидва записи | `qdrant-find` |

| Метрика роботи агентів | Офіційний MiniLM | ABox baseline |
|---|---:|---:|
| Правильні grounded-відповіді | 4/4 (100%) | 2/4 (50%) |
| Обрано очікуваний retrieval-інструмент | 4/4 | 2/4 |

Системний промпт baseline спрямовує питання про зв’язки/граф до Neo4j (`get-schema`/`read-cypher`), але до графа не завантажено жодного вузла; його корпус існує лише у векторній колекції ABox. Агент коректно утримався від вигадування відповіді, проте його агентний retrieval-шлях не може використати проіндексовані вектори для таких запитів. Офіційний агент працює лише з векторами й обрав `qdrant-find` для всіх чотирьох запитань, надавши відповіді з джерелами. Це обмеження корпусу/маршрутизації інструментів, а не доказ загальної переваги embeddings MiniLM: у прямому векторному пошуку baseline ранжував ціль вище (MRR 1,00 проти 0,75). Ці оцінки вимірюють різні рівні й не повинні змішуватися.

Окремо перевірений `k8s-agent` також успішно завершив A2A-запит, викликав `k8s_get_resources` і правильно повернув тип Service Qdrant (`ClusterIP`) та HTTP-порт (`6333`).

## Операційна примітка: перебудова official image

Кешований на worker image `qdrant-mcp-official:0.8.1` містив Pygments mapping-файл, повністю заповнений нульовими байтами; Python завершувався з `SyntaxError: source code string cannot contain null bytes`. Новий image зібрано з офіційного пакета `mcp-server-qdrant==0.8.1`, перевірено імпортом і завантажено на три kind-вузли під тегом `qdrant-mcp-official:0.8.1-rebuilt`. CRD тепер посилається на цей локальний тег. Тег не опублікований у registry, тому при створенні нового кластера його треба зібрати та завантажити повторно. Інструкції зі збирання офіційного Docker image є в [репозиторії Qdrant](https://github.com/qdrant/mcp-server-qdrant); використану версію пакета підтверджує [реліз v0.8.1](https://github.com/qdrant/mcp-server-qdrant/releases/tag/v0.8.1).
